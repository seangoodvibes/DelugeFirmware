# Parameter Integration Tests

These tests complement the serializer and value-binding unit tests with native
production-parser coverage. All parameter tests run on the host through CTest.

From the repository root:

```sh
cmake -S tests -B build/tests
cmake --build build/tests --config Debug
ctest --test-dir build/tests -C Debug --output-on-failure
```

## Focused unit tests

`UnitTests` includes six value-binding cases, three saturating `shift_value` cases,
and thirteen scalar/node serialization cases. They exercise the production binding,
arithmetic, and decoding helpers with small fixtures. Binding tests cover default
values, standalone copies, and switching owners. Arithmetic tests cover exact sums,
zero offsets, and clamping at both signed 32-bit limits. Parser tests cover invalid
and overflowing decimals and allocation failure when wrapping a legacy endpoint
node to zero while preserving existing nodes.

Decimal values must be complete base-10 integers with an optional leading minus,
at most 11 characters, and a value that fits in `int32_t`. Malformed, overflowing, or overlength decimals leave the
existing scalar unchanged. The reader consumes their remaining attribute text so
XML/JSON traversal can continue. Native parser tests check that behavior at every
cluster alignment; this does not change the hexadecimal automation format.

`object_pool_lifetime_spec` adds six host-only cases using a nontrivial object with
owned memory and constructor/destructor counters. They cover raw storage, resource
cleanup, reconstruction on reuse, moving managed pointers, and releasing acquired
objects after clearing, shrinking, or filling the pool. These test the existing
generic pool, not a future `AutoParamPool` or its exhaustion policy.

## Native Persistence Tests

`NativeParameterPersistenceTests` is a separate executable and registered CTest
test in the native `tests` project. Build this target using the native test
configuration, not the firmware cross-compilation configuration. It requires no
SD card or Deluge hardware.

It links the production XML/JSON serializers and deserializers, buffered
`FileReader` operations, integer formatter, and scalar/node decoding helpers.
Scalar encoding uses `write_current_value()`. Round-trip cases use production
writers for document framing, quoting, commas, indentation, and attributes;
node records are generated by the fixture. Earlier reader-only cases retain
fixture-generated documents as an independent input. Save-decision tests exercise
the shared `write_param_as_attribute()` helper used by
`ParamSet::writeParamAsAttribute()`. They cover neutral/nonneutral values, integer
limits, automation presence, scalar-only saving, omission, and overrides to/from
zero. Overrides apply only to automated parameters, matching `AutoParam::writeToFile()`.
Omission is based on the source before applying an override, and writes
must preserve both source values and automation. A counting automation adapter
verifies when node writing is invoked. Actual `ParamSet` object wiring and node
encoding through `AutoParam::write_automation()` remain outside the native target.

Coverage includes integer limits, legacy decimal strings, and 1,024-node payloads
at all 64 offsets of a simulated 64-byte cluster. Every node value, position, and
interpolation bit is checked, as is a following sentinel attribute. The small
cluster deliberately forces many refills through the production buffered reader.

Timeline-limit cases cover a first excluded node at or beyond the limit, with and
without an existing zero-position node, at every cluster alignment. They verify
legacy endpoint wrapping, retained node values/interpolation, summary flags, and
the next attribute after a multi-cluster unused tail. The reader consumes that
tail without retaining nodes, preventing JSON traversal from stopping inside it.

Truncation cases end the file at every byte of a hexadecimal scalar and three
node records, at all 64 cluster alignments. Disk-failure cases align each of those
cutoffs with a refill and inject persistent `FR_DISK_ERR` responses. Assertions
check bounded read attempts, scalar preservation for incomplete hex values,
complete-node contents/interpolation, removal of old automation, and summary flags.
A lone `0` remains a valid legacy decimal. A complete scalar and any complete
nodes before EOF/error are retained; partial records are discarded. This records
the current partial-load behavior, not transactional rollback or error reporting:
the shared loader still returns no error to its caller.

Allocation-failure cases inject failed first, second, and third node insertions,
plus failure to insert a legacy endpoint at zero, across all cluster alignments
in XML and JSON. They verify `INSUFFICIENT_RAM` from the node reader, the loaded
scalar, retained complete nodes, cleared interpolation, and unrelated summary
bits. Reservation failures are tested both with insertion failures and with
successful individual insertions. These use a controllable node-container adapter,
not the firmware allocator. They record partial-load behavior; rollback, error
propagation from `read_param()`, and parser recovery after failed insertion remain
unverified and are not guaranteed by these tests.

Writer reset tests discard an unfinished document and check exact formatting of
the next one. Reload tests exercise the same `read_param()` coordination used by
`ParamSet::readParam()`: scalar-to-automated, automated-to-different-automation,
automated-to-scalar (hex and decimal), and loading with automation disabled.
Repeated loads verify the scalar, replacement nodes, cleared interpolation flags,
and preservation of unrelated summary bits, including a target at bit 31.

The platform fixture supplies file bytes through `f_read`, a bounded output byte
sink, host buffer allocation, and no-op logging/background callbacks. Writer
buffer flushing and SD writes are not tested. Node storage uses `std::vector`;
the automation adapter clears nodes and delegates parsing to production
`read_nodes()`. It is not a real `AutoParam`, so these tests verify reload
coordination, not actual automation allocation/destruction.
Unsupported dynamic-string and firmware-metadata paths throw instead of silently
passing. These tests do not validate FatFS itself, the firmware allocator, actual
parameter ownership/cloning, undo callbacks, or real-time playback. Native coverage
of selected lifecycle cases is provided by the separate target below.

The native suite caught a decimal `INT32_MIN` bug: its 11 characters filled the
scalar reader's limit without consuming the closing quote, breaking traversal to
the next JSON attribute. The scalar reader now also reads the terminator.
Reload tests also caught ignored automation leaving JSON's cursor inside the
payload; the shared loader now consumes that payload without allocating nodes.
Writer reset coverage requires each serializer to initialize its own indentation
counter, which is distinct from the counter in `FileWriter`.

## Native Lifecycle Tests

[`NativeParameterLifecycleTests`](lifecycle/README.md) links real parameter sets,
automation, node containers, manager cloning/cleanup, and undo consequences. It
covers scalar edits, ownership, undo/redo, automation transitions, deterministic
playback, real-object XML/JSON persistence, and allocation failures without hardware. It also offers an AddressSanitizer configuration.
See its README for the platform boundary and remaining coverage gaps.
